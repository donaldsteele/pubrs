# M8: Templates, printing, installers, docs

What works:

- Four built-in templates (flyer, trifold brochure, business card, newsletter) plus user templates; printing
  through the native dialog on Windows/macOS and CUPS on Linux (both from M6/M7).
- `.github/workflows/release.yml`: one `v*` tag builds the x64 and ARM64 MSIs (cargo-wix), the universal macOS
  `.app` in a DMG (cargo-bundle + lipo, `.pubrs` document type), `.deb` and AppImage for x86_64 and aarch64, then
  installs each, runs the GUI smoke test, exports the bundled sample to PDF, checks the file association and
  uninstalls, and drafts a GitHub release. Flatpak manifest and AppStream metadata in `packaging/flatpak/`.
- Icons for the app and the `.pubrs` document type (PNG, ICO, ICNS) generated by
  `cargo run -p pubrs-io --example make_icons`; the GUI window uses the same icon.
- Sample publication `examples/samples/bakery-trifold.pubrs` (+ PDF), made by `examples/scripts/bakery-trifold.json`,
  ships in every installer.
- Dropping a `.pubrs` file on the window opens it and dropping a picture fills the selected picture frame; the GUI
  self-test reopens the saved brochure this way.
- USER_GUIDE.md (per-OS install, getting started, shortcuts, AI assistants, CLI) and RELEASE.md (signing,
  automated checks, manual per-installer check).

See it (Linux, verified locally):

```
cargo build --release -p pubrs-app -p pubrs-cli -p pubrs-mcp
cargo deb -p pubrs-app --no-build --output dist/            # dist/pubrs_0.1.0_amd64.deb
packaging/linux/build-appimage.sh target/release 0.1.0 x86_64 dist
dist/pubrs-0.1.0-x86_64.AppImage                            # GUI
dist/pubrs-0.1.0-x86_64.AppImage --cli export examples/samples/bakery-trifold.pubrs -o out.pdf
dist/pubrs-0.1.0-x86_64.AppImage --mcp                      # MCP server on stdio
```

Windows and macOS installers are built by the release workflow (Actions → Release → Run workflow).
