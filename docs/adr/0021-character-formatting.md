# 0021 Character formatting and missing glyphs

- Context: T9 (M17). Character properties gain `baseline`, `caps`, `strikethrough`, `ligatures` and `kerning` (schema 8), and `validate` has to name the characters no font covers. Locked Decision 2: a run with none of the new fields lays out exactly as in M16, and shaping stays one parley layout per paragraph.
- Decision:
  - **Fields.** All optional, skipped when unset, inherited through styles like the other character fields: `baseline` (`normal`, `superscript`, `subscript`, `{"shift": points}` with positive up), `caps` (`none`, `small`, `all`), `strikethrough`, `ligatures` (default on), `kerning` (default on). Unset resolves to the v0.1 behaviour.
  - **Only what differs is pushed to parley.** `push_attrs` still pushes the original seven properties; vertical alignment, font features and strikethrough are pushed only when a run's value differs from the paragraph default (or, for the default itself, when it is not the default value). A paragraph without the new fields builds the same style table as before, so every golden, the layout reference and the bakery test are unchanged.
  - **Superscript and subscript** use the face's OS/2 `ySuperscript*`/`ySubscript*` records: the size is `YSize / unitsPerEm` of the base size and the shift `YOffset / unitsPerEm` of the base size (OS/2 stores the subscript offset positive downward, so its magnitude is lowered). A record with a zero size or offset, or an implausible one (size outside 20-100% of the em, offset over 1 em), is ignored and 58% size with a 33% shift (down for subscript) is used. The face is the one parley picks for the run's family, weight and style, found once by shaping a letter and cached per (family, bold, italic) in the `Layouter`. The reduced size is the run's `FontSize`; the shift is parley's `VerticalAlign(BaselineShift::Length)`. Baseline shift is the same without scaling.
  - **Line height.** parley sizes a line to include every span's box at its shifted baseline, so a raised or lowered run grows its line (a 20 pt line with a superscript went from 24 to 26.9 pt) and the baseline moves down by the same amount; glyph positions, carets, decorations and the renderer need nothing. A custom shift of 30 pt makes the line 30 pt taller. Neighbouring lines are not squeezed, as in Publisher.
  - **Small caps.** If the face's GSUB feature list has `smcp` the run gets `"smcp" 1` and the font draws its own small capitals. Otherwise they are synthesized: each lowercase letter is drawn as its capital at 70% of the run's size (a separate parley range, so a mixed word is several glyph runs). No other text changes size. Real `smcp` detection reads the feature list only; it does not check that the lookups cover the letters.
  - **All caps and synthesized small caps never change story text or offsets.** The shadow text (the copy parley shapes, ADR 0014) maps a letter to its capital only when `to_uppercase` yields exactly one character of the same UTF-8 length; 'ß' (uppercases to "SS") and 'ı' stay as they are. So the shadow keeps one character and the same byte offsets per story character, and `Shadow::to_orig`, carets, selection, find and spelling are untouched. Capitalisation is display only: copy gives the typed text. Drop caps map the same way.
  - **Ligatures and kerning** are font features: `"liga" 0, "clig" 0` and `"kern" 0`, joined with `smcp` into one `FontFeatures` string per run.
  - **Strikethrough** is a decoration rect like the underline (`strikethrough_offset` and `size` from the font metrics, at least 0.5 pt), split at tab segments the same way. In a synthesized small-caps word the rule follows each glyph run, so it steps between the two sizes.
  - **Missing glyphs.** `StoryLayout.missing_chars` (a `BTreeSet<char>`) is filled with the characters of glyph id 0, read from `PositionedGlyph.text` into `GlyphRun.text` (controls excluded; `missing_glyphs` still counts every glyph). `validate` reports `WarningCode::MissingGlyphs`, a new variant, with the count and up to 20 names: `no available font covers: ✓ (U+2713), …`. `MissingFont` stays for families; T21 reuses `MissingGlyphs`.
  - **Glyph text ranges across runs.** The per-paragraph cache of cluster groups was keyed by `Run::cluster_range().start`, which counts from the start of each shaped run, so every shaped run on a line shared key 0 and later runs got the first run's clusters (their glyphs fell back to an empty text range). The key is now the run's text start. Mixed-size lines (super/subscript, small caps) need the right ranges; the layout reference does not store them, so nothing else moved.
  - **Cache.** Character props are part of the story, so toggling them recomposes exactly that story; a test toggles all five and compares incremental with full layout, and the property test draws them.
- Consequence:
  - Fonts without OS/2 script records, or with absurd ones, get 58% / 33%; a face with `smcp` for only some letters still draws the rest with the font's own fallback.
  - A strikethrough through synthesized small caps is stepped.
  - The probe cache is keyed by family name, so adding a different font under an existing family name to a live `Layouter` is not noticed until the layouter is rebuilt.
  - `Cmd/Ctrl+=` and `Cmd/Ctrl+Shift+=` are subscript and superscript (Publisher's keys), so Zoom In moved to `Cmd/Ctrl+Alt+=`; the zoom buttons and `Cmd+-` are unchanged.
