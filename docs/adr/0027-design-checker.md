# 0027 Design Checker: warnings, commercial context, incremental panel

- Context: T21 (M29). Publisher's Design Checker lists problems by page and jumps to them; pubrs had `validate` (a flat list) and a modal Check for Problems dialog. M29 adds the missing checks, a panel that stays current while the user edits, and a check before a commercial export.
- Decision:
  - **Warning shape.** `Warning {code, message, hint, page, frame}` gains `frames: Vec<FrameId>` (`#[serde(default, skip_serializing_if = "Vec::is_empty")]`) for issues that involve several objects; `frame` stays the primary one. Today only linked text chains set it (overflow, missing font, missing glyphs on a chain of two or more frames); single-frame warnings are byte-identical to before. New `WarningCode` values (snake_case): `rgb_in_cmyk_job`, `text_too_small`, `low_contrast_text`, `object_in_unprintable_area`, `empty_table_cells`, `missing_alt_text`. `missing_glyphs` already existed and still names the characters. A `Warning` is not part of the saved document: no schema change.
  - **Commercial context is a request flag, not a document setting.** The document has no colour mode. `validate` takes `ValidateIn {doc_id?, commercial: bool = false}` (`deny_unknown_fields`; old `{doc_id}` calls and `Session::validate(DocRef)` still work). `rgb_in_cmyk_job` is emitted only when `commercial` is true; it also turns off the desktop-margin check. `pubrs validate --commercial`, a checkbox in the panel (off by default) and the pre-export check (always true) set it.
  - **Core split.** `validate_page(doc, page, opts)` returns the frame-level warnings of one page; `validate_document(doc, opts)` the story-level ones (hyphenation); `validate_with(doc, opts)` is their concatenation and `validate(doc)` is `validate_with` with the defaults, so its output for the old codes is unchanged. `Session::validate_parts(doc, commercial, pages)` adds the layout-based warnings (overflow, missing fonts, missing glyphs, undecodable images) and checks only the pages asked for; `Session::validate` is `validate_parts` for all pages, flattened.
  - **The checks.**
    - `rgb_in_cmyk_job`: an RGB use in a frame's fill, outline or shadow, WordArt fill, outline or shadow, a table cell fill or border, a gradient stop, or a run's resolved text colour. RGB means `Paint::Color` (alpha above 0) or a swatch whose value is RGB; CMYK and spot swatches pass. One warning per frame listing the uses. Pure black text (`#000000`, the default text colour) is not counted, or every text frame of every document would be flagged. Raster images are not judged (they are sRGB; PDF/X-4 carries them ICC-tagged, ADR 0018).
    - `text_too_small`: `MIN_TEXT_PT = 6.0`, on the resolved size (`StyleSheet::resolve_char`) of runs with visible text, and on WordArt size. One warning per frame naming the smallest size; for a table, the first small cell's position (1-based row and column).
    - `low_contrast_text`: WCAG relative luminance and contrast ratio (`Color::relative_luminance`, `contrast_ratio`, unit-tested). Warns below 3.0 (`MIN_CONTRAST_RATIO`). Background: the frame's own fill if it is opaque enough (alpha times frame opacity at least 0.5; a gradient counts when its mean alpha does, and every stop is checked); for table text the cell fill comes first, then the frame fill; otherwise the topmost frame beneath it on the page whose bounds hold its centre and that has an opaque fill; otherwise white (there is no page background). A picture beneath is "unknown": no verdict. The worst ratio is reported with both colours. (The plan said stacked frames are ignored; checking one level of fills beneath was needed to keep white text on a banner, as in the flyer and newsletter, from being flagged.)
    - `object_in_unprintable_area`: `UNPRINTABLE_MARGIN_PT = 18.0` (0.25 in). A frame with visible content (non-blank text, a picture with an image, a shape with a fill or outline, WordArt with text, a table) whose bounds enter the outer band, only when bleed is 0, the check is not commercial and the page setup has no label sheet. Frames already reported off the page or beyond the bleed are not reported twice. The built-in newsletter's full-width masthead band therefore carries this warning: it is correct for a desktop printer.
    - `empty_table_cells`: cells whose story is blank after trimming; the count and the first 10 positions.
    - `missing_alt_text`: pictures with an image and no alt text. WordArt and shapes have no alt-text field (TODO).
    - `merge_field_missing` is not in this branch: mail merge (M24) is paused elsewhere and defines its own `MergeFieldMissing`. No placeholder variant is added; M24's rebase plugs its warning into `validate_page` (the checker, the panel and the export check need no change; add the code to the panel's problem list if it should count as a problem).
  - **Dangling swatches are integrity errors.** `Document::dangling_swatches` (swatch.rs) walks frame fills, outlines, shadows, WordArt, table cells (`extra_paints`), run colours and style colours, gradient stops included; `check_integrity` appends its messages. Swatches exist since M21 (unreleased), so no shipped file can fail on load.
  - **The panel** (`crates/pubrs-app/src/checker.rs`). A bottom panel (`egui::Panel::bottom("checker")`, resizable, 200 pt) added after the pages and properties panels, so the page keeps its width and the list reads wide; Review → Design Checker toggles it, and the toolbar Check button and View → Check for Problems… open it (`Dialog::Validation` is gone). Issues are grouped by page ("Page 3 (2)" collapsing headers, then "Publication"), each with a Problem or Check label, the message and the hint; a click goes to the object (page, selection, scroll; the same as find's `goto`).
  - **Refresh cost.** Once per frame the panel compares the document revision. A change starts a 400 ms timer (and `request_repaint_after`); each further change restarts it. After 400 ms of quiet it checks only the pages whose content changed and rebuilds the story-level warnings from the cached layout. A page's content is its frames and their stories (table cells included), kept as `Arc`s and compared by pointer then value (commands replace only what they touch, ADR 0012); setup, swatches, styles, assets, the commercial box or another document invalidate every page. A unit test pins that a one-letter edit on a 20-page document checks 1 page, not 20. It runs on the UI thread because it needs the session's layout, never on the keystroke, and not at all while the panel is closed.
  - **Before a commercial export.** With the Commercial preset (and for Save for a commercial printer… from the dialog or the File menu, which is always a PDF/X-4 job), the Export dialog runs `validate` with `commercial = true` before the save prompt and keeps the blocking subset: `missing_font`, `rgb_in_cmyk_job`, `low_resolution_image`. If there are any they replace the options: Export anyway (carries on, and does not ask again in that dialog), Fix first (closes the dialog, opens the panel with the commercial box on, selects the first issue) and Cancel. Other presets never block.
- Consequence:
  - Frames beneath a text frame are judged one level deep and only by their own fill: a gradient or picture beneath, partly covering fills, rotated frames (bounds are used) and fills stacked several deep are approximations. Text on a picture is not judged. (TODO)
  - The checker works on whole documents' frames of pages only; master-page frames are not checked (as before).
  - `object_in_unprintable_area` assumes 18 pt on every side; a printer's real margins differ. It skips label sheets (a TODO).
  - The first check after opening the panel, and a new setup, styles or swatches, check every page: is not measured on big documents; it is off the keystroke path but on the UI thread (TODO: measure, and move the model-level part to a worker if it shows).
