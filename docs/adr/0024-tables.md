# 0024 Tables

- Context: T11 (M19). Publisher tables have merged cells, per-cell fills, borders, insets and vertical alignment, and text that grows its row. Locked Decisions 1 (every change a command), 2 (additive schema), 3 (an edit costs what it touches) and 4 (deterministic output) bind.
- Decision:
  - **Model.** `FrameContent::Table(Box<TableFrame>)` (schema 11, identity migration). `TableFrame { cols, rows: [{min_height}], cells }`; each cell has its top-left `row`/`col`, `row_span`/`col_span`, a `story`, `fill`, `borders` (top, right, bottom, left, each optional), `insets` and `valign`. Every grid position is covered by exactly one cell, cells are kept in row-major order of their top-left position, and a cell story's chain is `[table frame]`. `check_integrity` verifies sizes, spans, coverage and that every cell story exists, lists only its table and is used once. `Document::story_of` stays text-only; `cell_of_story` and `table_of_story` find a cell's table. Deleting a table removes its cell stories (`remove_frames`). The frame's width follows the column sum: column commands set it, and `SetFrameRect` (and group resizing) scales the columns.
  - **Commands.** Ids are allocated by the caller (ADR 0005): `AddTable { frame, stories }` (one new story per cell; `AddFrame` refuses a table), `TableInsertRows`/`TableInsertCols { at, count, stories }` (one story per new cell; a merged cell crossing the insertion point grows instead, so the caller asks `insert_rows_needed`/`insert_cols_needed`), `TableDeleteRows`/`TableDeleteCols` (cells wholly inside go with their stories, others shrink; at least one row and column stay), `TableMergeCells` (the top-left story is kept, absorbed cells' paragraphs are appended in row-major order, their stories removed; a range cutting through a merged cell is refused), `TableSplitCell { stories }` (unmerge to single cells; new cells copy the style), `TableSetCellStyle` (whole style replaced; the tool merges), `TableSetColWidth`, `TableSetRowHeight`. All invert through the generic patch, so undo is exact; the patch corpus gained table steps (append only).
  - **Layout.** Each cell story has one region in cell-local space: x = left inset, y = top inset, width = the spanned columns minus insets, height = 20,000 pt (`CELL_FLOW_HEIGHT`). The flow therefore measures a cell without knowing where it sits; its key changes with the spanned width and insets only, so a keystroke recomposes one cell. The table pass (`pubrs-layout/src/table.rs`) then sets row height = max(min height, tallest single-row cell's last line + bottom inset), a spanning cell's shortfall going to its last row; clips the rows to the frame's bottom; places the cell rectangles; applies each cell's vertical alignment as an offset `dy` (stored, not baked into the lines); and finds overflow. A cell whose lines reach below its clipped rectangle keeps the lines that fit and gets `StoryLayout.overflow` (offset of the first hidden line, hidden characters), so `text_overflow_status`, `frame_get` and `validate` report it; a cell below the bottom with text overflows, an empty one does not. `DocumentLayout.tables` holds the `TableLayout` per frame; a table is never looked up through `layout.frame(id)` (ambiguous with many stories): use `cell_text(frame, story)` and `cell_origin(frame, story)`.
  - **Cache.** `StoryLayoutCache` caches the table pass per frame, valid while the frame `Arc` (or value) and every cell's raw story layout `Arc` are unchanged (`CacheStats.tables_recomposed`/`tables_reused`). Overflowing cells' trimmed layouts are cached with it, so the `Arc`s stay stable. `PUBRS_LAYOUT_VERIFY` compares tables as well as stories.
  - **Output.** The scene's Table arm draws, in frame-local space, cell fills (rectangles), each cell's glyph runs and decorations moved to the cell origin, then borders. A border two cells share is drawn once: segments on one grid line are cut by later cells' segments, so the later cell wins where both set one, and a missing border has no opinion. Borders are centred on the grid line, with ends extended by half the width so corners close. PDF export draws the same primitives (artifacts and text spans; no Table structure element yet). Tiles and damage use the ordinary primitives; a table is damaged whole when its row geometry or any cell's layout changed, since one keystroke can move every row below.
  - **API.** `pubrs-api/src/tools/tables.rs`: `table_add`, `table_get`, `table_set_cell_text`, `table_insert_rows`/`_cols`, `table_delete_rows`/`_cols` (confirm), `table_merge_cells`, `table_split_cell`, `table_set_cell_style` (a range of cells, per-side borders), `table_set_col_width`, `table_set_row_height`. Text, find, style and validate tools address a cell by `story_id`; a text tool given a table `frame_id` says so and points at `table_get`.
- Addendum (M20, GUI): the frame's height is still only a limit, so the GUI makes the frame follow the rows: after a structural command (insert or delete, row height, merge) `SetFrameRect` to the layout's `natural_height` joins the same undo step (`tables::run` merges it under the command's key), and every GUI command on a cell story (`PubrsApp::exec`/`exec_merge`: typing, replace, character and paragraph formats) does the same under its own undo key, so one action is one undo step. Edits through the MCP tools do not grow the frame. A range of cells is a rectangle stored in the view (`DocView.table_sel`), never in the document; ids for inserted cells are allocated before the command is built (ADR 0005). Borders are found from the cached `TableLayout` and the column widths only.
- Consequence:
  - Splitting only undoes a merge; inserting a row or column is how a grid gets bigger.
  - A cell is as tall as its row; lines are never split across the frame's bottom, so a partly visible cell shows only whole lines.
  - A table's frame height is a limit, not a size: rows below it have no height and their text is reported as overflow.
  - Rows do not shrink the frame; the frame's height is not updated to the rows' total.
