# 0023 Mail merge

- Context: T16 (M24). A design with merge fields is printed once per record of a list (CSV or XLSX), on screen shows «Name» or the previewed record's value, and works with label sheets (M23). Locked Decisions: story offsets stay in characters (Section 3), layout and the cache stay incremental (3), the data lives in the document so it reopens without the file (Owner decision 4), and a document without merge fields lays out exactly as before (2).
- Decision:
  - **Data.** `Document.merge: Option<MergeSource>` holds `source_name`, `kind` (`csv`/`xlsx`), `sheet`, `fields`, `records` (an `Arc<Vec<Vec<String>>>`, so document clones and patches stay cheap), `preview_index` and `preview`. Every row has one cell per field (short rows padded with ""). Setting, refreshing and clearing the data is `SetMergeSource`; the preview record and switch are `SetMergePreview` (the GUI coalesces consecutive steps into one undo step). `Patch` gained `merge` (a slot that can also be "none"). Limits, enforced by the command and reported by the readers: 100,000 records, 1 MB per cell, 512 fields. The file path is not stored; the session remembers it so "Refresh data" (`merge_set_source {refresh: true}`) re-reads it as one undo step and keeps the preview.
  - **Readers.** `pubrs-io/merge_source.rs`. CSV is parsed in-tree (RFC 4180: quotes, doubled quotes, line breaks in quotes, CRLF/LF/CR; a BOM is ignored; the delimiter, comma, semicolon or tab, is whichever is most frequent in the header line outside quotes; blank lines are skipped; invalid UTF-8 and an unclosed quote are errors). XLSX uses `calamine` 0.36.1 (MIT): the first sheet or the one named (exact, then case-insensitive), cells as the text a person sees (whole numbers without ".0", dates as `YYYY-MM-DD` or with `THH:MM:SS`, errors as ""). Headers are trimmed; blank ones become `Column N`, repeats get ` 2`, ` 3`.
  - **Resource limits.** Input is capped at 64 MiB (CSV text, files, workbooks). Records are capped at 100,000, fields at 512, bytes per cell at 1 MB, and cells (records x fields) at 5,000,000, checked before any row is padded and again by `SetMergeSource` and `check_integrity` (so an inline CSV over MCP and a `.pubrs` read from disk obey the same caps). An XLSX is first opened with the `zip` crate: at most 4096 parts, 256 MiB uncompressed in total, and a part over 1 MiB that expands more than 200x is refused as a bomb; the workbook is then written again as a new zip: part names are compared as calamine does (`\` as `/`, ASCII case ignored) and duplicates refused, each part is inflated for real (declared sizes are not trusted), and any `...sharedStrings.xml` (at most 64 MiB, 5,000,000 strings) is re-serialised with quick-xml with its `<sst>` attributes replaced by the real string count, so calamine never reserves for a number the file made up. Total text stored is capped at 64 MiB. The sheet is read with calamine's streaming cell reader and rows are built sparsely, so cells at A1 and XFD1048576 cost two cells (and are refused for row and column limits). A merge may make at most 20,000 pages (records x pages).
  - **Fields.** One U+FFFC character in a run of its own with `field: Some(name)`. `Run::same_format` is false whenever either run is a field, so `normalize_paragraph` never merges one, and typed text or a format change beside a field never makes it part of a run. `InsertMergeField` is one command (one undo step); with data loaded the name must be one of its fields (the error lists them).
  - **Display: the edit table.** The M14 `Shadow` modelled only inserted soft hyphens (2 bytes each). It is now `Shadow { text, edits }` where an `Edit { at, len, orig, orig_len, shy }` says that shadow bytes `at..at+len` stand for story bytes `orig..orig+orig_len`; a soft hyphen is `(len 2, orig_len 0)`, a field shown as "Ann" is `(len 3, orig_len 3)`, an empty value that takes a space is `(len 0, orig_len 4)`. `to_orig`, `from_orig` and `to_display` are binary searches that read only the neighbouring edit (the edits are ordered and disjoint, so the last one before the byte gives the offset). A byte inside a shown value maps to the field's start, one just after it to just after the field; a story byte inside a collapsed range maps to the start of its shown text. `Shadow::substitute` applies the fields after hyphenation and moves the soft hyphens that follow. Everything that counted characters through "shadow chars minus soft hyphens" now counts on the story text through `to_orig`, which is the same number when there are no fields.
  - **Carets, selection, find, spelling.** They stay on story text. A field is one caret unit: `field_caret_positions` walks the story's character boundaries of a line and puts each at its place in the shadow text, so a line holds one caret per story character plus one, whatever the field shows. Letter-spacing on justified lines is added per displayed character. M26 find matches the U+FFFC; M28 spelling already skips words with it.
  - **Glyph ranges.** `GlyphRun.text` holds the displayed text (the story text with fields shown, without inserted soft hyphens) and a glyph's range indexes it, so a PDF's text (ToUnicode) is the merged text. Without fields it is the story text, as before. Tab positions are mapped into the same coordinates.
  - **Drop caps, tabs, caps.** A drop cap never takes a field (the cap stops before it), and a collapsed space never reaches into one. Tabs, all caps and small caps are layered on the shadow text, so they see the shown value. A test lays out a field-and-text paragraph and the same text typed in place, with drop caps, tab stops with leaders, all caps, and hyphenation with justification after the field, and requires identical glyphs, positions and line boxes.
  - **Cache key (Risk 1).** Field display reads document-level data, not the story, so `StoryKey` has `merge`: for a story that contains field runs and a document with merge data, the preview switch and, per distinct field name, the previewed record's value (or none, for «Name»). Stories without fields, and documents without data, add nothing. Stepping a record or toggling the preview recomposes exactly the stories with fields; `PUBRS_LAYOUT_VERIFY` and a test that steps, toggles, undoes and clears compare the incremental layout with a full one.
  - **Collapse rule.** A field whose shown value is empty (after control characters become spaces and the ends are trimmed) takes one adjacent space with it: the space after the field if there is one, else the space before it; a space is never taken twice. A field with no value shown (preview off, no data, or a name the data lacks) shows «Name» and takes nothing. Line breaks and tabs inside a value become spaces: a value is one line.
  - **Output.** *Merge to PDF* (`ExportContext::export_merged_pdf`): for each record a document clone with that record previewed is laid out through one `StoryLayoutCache` (stories without fields are shaped once) and its page scenes are appended; the whole run is then imposed once. *Merge to a new publication* (`merge_to_publication`): per record the stories used by the pages are copied with the fields replaced by text (`realise_story`, keeping each field run's formatting), and the pages, frames and stories get ids derived deterministically from the originals and the record number (record 0 keeps its ids); master pages are shared, so fields on a master stay as «Name» there. *Print* sends the merged PDF.
  - **Label sheets.** The design is one label. On a `Sequence` sheet the merged pages fill the cells in order, so 30 records on Avery 5160 are one sheet of 30 cells and record 31 starts the second sheet. On a `Repeat` sheet each record's page fills a sheet of its own. A booklet is imposed over the whole run (records are not padded to a multiple of 4 each).
  - **Validate.** `WarningCode::MergeFieldMissing`, emitted by `validate_document` (stories, including table cells, are scanned on every Design Checker refresh, so changing the data or a record refreshes it without a page key): a field that names a column the loaded data lacks (once per story and name). With no data loaded there is nothing to compare with, so no warning; the merge itself is refused with a hint (`no merge data`, `no records`, `no merge fields`).
  - **GUI.** Mailings ▸ Mail Merge… is a four-step wizard (Data with a path field, a file chooser and a sheet picker; Fields; Preview with ◀ ▶ and the arrow keys; Finish to PDF, publication or print), Mailings ▸ Refresh Data, and Insert ▸ Merge Field… (a picker, arrow keys and Enter, disabled with a reason when there is no data or no caret). Fields are drawn with a faint amber tint over the page image.
  - **Address labels template (M30).** `address_labels` carries merge fields Name, Address, City, State and Zip in its one frame (still the `address` placeholder); with a list holding those columns it validates clean, with one lacking a column `merge_field_missing` fires, and 30 records merge to 30 labels on one 5160 sheet (`SheetFill::Sequence`). Its golden now shows «Name», «Address», «City», «State» «Zip».
- Consequence:
  - Copying text that contains a field through the clipboard gives plain text, so the pasted U+FFFC is an ordinary character (drawn as a missing-glyph box) until the field is inserted again.
  - Field values are one line; a multi-line cell (an address) needs one field per line.
  - A merge of 100,000 pages holds every page scene until the PDF is written.
  - `zip` 8 (from `calamine`) and `zip` 9 (the workspace) are both in the tree.
