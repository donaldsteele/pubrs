# 0017 Publisher (`.pub`) import: own parser, bounded reads, three file generations

- Context: Owner decision 9 of the Publisher-parity plan asks for import of Microsoft Publisher files. The format is undocumented. The open-source readers are libmspub (MPL-2.0, C++) and Apache POI HPBF (Apache-2.0, Java, text extraction only). The corpus in `tests/corpus/pub/` has 28 files: 22 that LibreOffice converts and six crafted or fuzzer files that it does not. T23 (M31) covers the container, pages, text frames and text; T24 adds pictures, shapes, colour schemes and tables.
- Decision:
  - **Own parser, format references only.** libmspub and POI HPBF were read as format references for record ids, offsets and chunk layouts. No code is translated or copied from either; the Rust structure (`pubfile/{container,records,text,report,mod}.rs`) is ours, and the layout notes at the top of `records.rs` are written from what the corpus files contain. The libmspub clone lived outside the repository and was never built or run.
  - **Container.** `cfb` 0.14 (MIT) reads the OLE compound file. Streams are read whole into memory, each capped at 64 MiB, and the input at 256 MiB.
  - **Version handling.** The `Contents` stream starts `E8 AC <v> 00`:
    - `v = 0x2C`: Publisher 2002 and later (the corpus goes to 2010). A trailer holds a directory of typed blocks; each block has an id byte, a type byte that fixes its length class (fixed 0, 2, 4, 8, 16, 24 bytes, or variable with a 4-byte length) and data. Chunks (document, page, shape, palette) are found through the directory. Shape geometry comes from `Escher/EscherStm` (Office Art records, with Publisher's 4-byte tail after the DGG and DG containers and a duplicated length at the start of client-data and client-anchor records). Text comes from `Quill/QuillSub/CONTENTS`.
    - `v = 0x22` with a Quill storage: Publisher 98 or 2000 with Quill text. A flat chunk table (10-byte entries) at the offset in the header; each chunk starts with a type marker; shape geometry is inside the shape chunks. The corpus files `Sample98` and `Sample2000` both have this form.
    - `v = 0x22` without a Quill storage: Publisher 98 proper. Text is inside `Contents` as single-byte text with Word-style 512-byte property pages (`fdo59355-1`). It has no code-page field, so it is read as Windows-1252; text in another code page is therefore wrong (the Russian sample reads like libmspub's own output for it).
    - Any other version byte is `IoError::Format("pub: unsupported Publisher version byte 0x..")`, naming the byte.
    - Unknown blocks, chunk types and Escher records are skipped and counted in `ImportReport.dropped`.
  - **Pages.** Pages come from the document chunk's page list. Master pages (a non-empty master name) and placeholder pages (listed but with no shapes) are not pages. A genuinely empty page in a user's document is indistinguishable from a placeholder in these files, so it is not imported (TODO). Page size is from the document chunk; every page has that size. Margin guides are not read yet; the page margins are 36 pt.
  - **Frames and chains.** A text shape names a story by text id. Shapes with the same id are one story; the head carries the text and `LinkFrames` links the rest. The flow order follows the previous/next shape ids stored in the shape chunk (SampleNewsletter's three-column stories come out left to right), falling back to page order. Shapes inside groups are placed on the page of their nearest listed ancestor. Rotation is read and set, insets, columns, column gap and vertical alignment come from the shape properties.
  - **Text.** Quill stores UTF-16 text and property runs (end offsets in the stream). A story is cut into paragraphs at the paragraph runs and into spans at the character runs. Bold and italic are toggles against the paragraph's default character style, as in the file. Font (by index into the font table), size, underline and colour (palette or RGB) map to `CharProps`; alignment, line spacing, space before and after, and indents map to `ParaProps`. Control characters other than tab are dropped; a vertical tab becomes a space.
  - **Robustness boundary.**
    - One parse budget (`ImportReport` carries it) covers the whole import: 1,000,000 kept items across every file-driven collection (fonts, colours, palette, lengths, ids, page list, pages, shapes, spans, paragraphs, stories, styles, Escher records) and a work allowance of 8 bytes per input byte plus 1 MiB, where each block walked costs its bytes plus 16. Each (stream, offset, kind) chunk is parsed once; repeats are reported as `duplicate-chunk`. Running out gives a `truncated` report entry and a partial import; the style limit (20,000 records, 2 KiB each) gives `style-budget` and `style-truncated` entries. Valid corpus files trigger none of these.
    - Every read goes through `Bytes`, which returns `None` past the end. Counts and offsets from the file are clamped to the size of the stream they point into before anything is allocated; block walks and Escher walks stop after 200,000 items; nesting stops at 64 levels; a page listed twice is read once. The document builder stops at 2,000 pages and 20,000 frames and reports the rest as dropped.
    - `pubfile::import` wraps the work in `catch_unwind` and returns `IoError::Format("pub: internal error while reading the file")` on any panic, so a bug in the parser cannot take down the GUI or the MCP server.
    - The tests fuzz three layers with proptest: random bytes and truncated or mutated whole files (through the container), and mutated or truncated streams with 32-bit "huge value" edits (straight into the record parsers). The fuzz entry points skip the `catch_unwind` boundary, so a panic fails the test instead of being converted.
- Consequence:
  - **How the oracle counts text.** libmspub writes a story's whole text into every frame that shows it, so a three-frame chain appears three times in the reference text (SampleNewsletter: 3,306 words). pubrs keeps one copy per story. The recall check therefore counts the text of every text frame (a story in a chain of N frames counts N times), which is what the reference does. The test also prints the plain per-story recall (0.451 for SampleNewsletter); only the per-frame figure is held to 0.90.
  - Both measures are enforced at 0.90: per-frame recall (above) and per-file distinct-word recall (all stories pooled), the share of the oracle's distinct words found anywhere in the imported text with each story counted once, which does not depend on duplication (SampleNewsletter 0.901, every other file 0.917 or more).
  - Pictures, shapes, tables, masters and colour schemes were listed as dropped chunk types until T24; ADR 0026 imports them.
  - The three `EDB-*` exploit files and the three clusterfuzz files fail in the container (bad magic or malformed FAT) with an `Err` in under a millisecond.
  - The corpus is the only specification, so unusual files may import with missing text; the report says what was skipped.
