# 0020 WordArt, drop shadows and BorderArt

- Context: T17 (M25). Publisher users expect WordArt (decorative warped text), drop shadows and BorderArt. Owner decision 8: WordArt is its own frame kind (one paragraph, warped as a whole), not a character effect. Owner decision 11: the BorderArt patterns are original SVG, CC0, twelve at launch. Locked Decision 4: output stays deterministic and tiled rendering stays byte-identical; Locked Decision 3: no edit does work proportional to the document.
- Decision:
  - **Model (schema 9).** `FrameContent::WordArt(WordArtFrame {text, font, size, warp, fill: Paint, outline: Option<Stroke>, shadow: Option<Shadow>})`, `FrameStyle.shadow: Option<Shadow {offset_x, offset_y, blur, color, opacity}>` and `FrameStyle.border_art: Option<BorderArt {pattern, width}>`. All new fields are optional and skipped when unset, so older files and the patch corpus are unchanged (the corpus only gained steps at its end). `SetWordArt` replaces a WordArt frame's content; shadow, border and WordArt fields are checked in `command.rs` (shadow offsets within 200 pt, blur 0 to 50, opacity 0 to 1, no gradient colours, known pattern, width 4 to 72 pt, text at most 200 characters, size 1 to 1000 pt). Swatch deletion and `replace_with` see the new paints.
  - **Shaping and cache (`pubrs-layout`).** `Layouter::layout_wordart` shapes the text once on one line (parley, same font library as stories) and returns a `WordArtLayout {runs, width, missing_font}` with the baseline at y = 0. `DocumentLayout.wordart` holds one per WordArt frame. The cache key is the text, family, size and the font library fingerprint: warp, fill, outline, shadow and the frame size are not in it because they are applied at render time, so changing them re-shapes nothing. `PUBRS_LAYOUT_VERIFY` compares them with a full layout like stories. Cost per layout pass: one comparison per WordArt frame (an iteration over the frame map, which is already walked for stories).
  - **Warps (`pubrs-render/src/warp.rs`).** Outlines are read from the font (skrifa) in text space (x along the baseline from 0 to the line width `W`, y down) and each point goes through the warp; `u = x / W`, `em` is the size. Slant up and down are `Y = y -/+ 0.2 x` (affine: curves stay curves). Wave is `Y = y + 0.28 em sin(2 pi u)`. Arch up and down put the baseline on a circular arc of 150 degrees (radius `W / angle`, so its length stays `W`) with letters radial: up uses radius `R - y` (tops away from the centre), down uses `R + y` (tops towards it). Circle is arch up round 0.97 of a full turn from the top. Inflate scales the distance from the middle of the text's height by `0.5 + 0.8 sin(pi u)`. Non-affine warps flatten lines to pieces of at most `em / 10` and curves to 8 or 10 pieces first. The result is scaled down (never up) to fit the frame, with room for the outline, and centred: `size` is the nominal size and the frame is the limit. The path is returned relative to its own box so a gradient fill spans the letters. The warp maths uses f64 `sin` and `cos` like `Affine::rotate` does (and gradients), so it relies on the platform math library the same way; coordinates are rounded to f32, so sub-ulp differences cannot change pixels except at exact rounding ties.
  - **Vector primitive.** `Prim::Path {path: Arc<PathData>, fill, stroke, origin, size, text}` where `PathData` is move/line/quad/cubic/close segments with a lazily built tiny-skia path. Raster draws it with `fill_path` and a round-join stroke; PDF draws vector outlines (no font is embedded for WordArt; in a tagged PDF the path is a Span with `ActualText` set to the string, so readers and copy-paste still see the words); the GPU path draws it through kurbo; `tiles.rs prim_box` and `damage.rs frame_bounds` include its box and stroke.
  - **Shadows.** The node (all of a frame's primitives, which for a WordArt are its letters) is drawn on a transparent layer; its alpha is blurred and tinted with the shadow colour times its opacity, offset, and composited under the node inside the node's opacity group. The blur is three horizontal then three vertical box passes of radius `r = ceil(blur_px / 2)` (so the reach is `3 r`, about 1.5 times the blur radius), window `2 r + 1` taking zero beyond the edges, rounded to nearest, in integer arithmetic and fixed order, so the bytes are identical on every platform. The offset is rounded to whole device pixels. Only the part of the layer that can reach the page is drawn. Damage grows a frame's bounds by the offset and `3 blur + 2` points.
  - **Tiles stay exact.** A scene with any shadowed node is drawn by the untiled renderer and cut into the requested rectangles, the same fallback M23 used for clipped (imposed) nodes, so the tiled output equals the untiled output by construction. `tests/tiles.rs` has a `shadows` page (and an `effects` page of WordArt and BorderArt, which does tile). The GPU backend has no blur: `Rasterizer::render_rgba` draws pages with a shadow with tiny-skia.
  - **Shadows in PDF.** The shadow of each node is an RGBA image at 150 dpi (capped so neither side passes 4,096 pixels, halving the resolution if it would) whose alpha is the blurred silhouette, drawn in page space under the node inside its opacity group. krilla writes the alpha as a soft mask, so it needs no transparency trick of ours. In PDF/X-4 and PDF/A-2b the image and its mask are ICCBased (`no_device_cs`, ADR 0018) and `pdfx::check` passes; `fixtures_pdf` has an effects document in both standards. The shadow is an artifact in tagged PDFs. It is a bitmap: a shadow is soft by nature, and a vector approximation of a blur would need a mesh or many transparent layers, with no benefit.
  - **BorderArt.** Twelve patterns drawn for pubrs, CC0 1.0, in `assets/borderart/` (ASSETS.md): `<name>-tile.svg` (repeated along an edge) and `<name>-corner.svg`, both 32 x 32 user units, compiled in with `include_bytes!` and parsed once with usvg. For a frame `w` x `h` and border `bw`, the four corners are `bw` x `bw` squares and each edge holds `round(length / bw)` tiles (at least one) stretched so a whole number fits; a tile's outer side faces out, so patterns with a direction (arrows) run clockwise. Tiles are `Prim::Svg {tree, transform, clip}` drawn with resvg in raster (the same path as pictures, windowed in tiles) and with krilla's SVG support in PDF, so they are vector in PDF. Rotation uses exact quarter-turn matrices. A frame too small for two corners and a tile on each side draws no border. Text frames lose `width` from their text area on every side (`regions_for`, so the layout cache key follows). The colours of a pattern are fixed.
  - **Find, replace and spell.** `text_find` also reports WordArt text: such a match has `story_id: null` and the WordArt's `frame_id`; `text_replace_all` edits it with `SetWordArt` in the same batch (one undo step). The GUI Find bar selects the WordArt frame (it has no caret); Replace replaces the first match in the selected frame; Replace All is the tool. Spell check does not look at WordArt text (TODO.md): the spell worker's results, squiggles and Change all belong to stories.
  - **GUI.** Insert ▸ WordArt… opens a gallery of twelve styles (a warp with a fill, outline and shadow), previewed with the real renderer; Format ▸ Shadow toggles a default shadow on the selection and Format ▸ Border Art… picks a pattern and width with previews. The properties panel has Shadow and Border art controls for every frame and a WordArt section (text, font, size, shape, letter fill, outline, letter shadow). All of it is reachable from the keyboard (Tab order, arrow keys in the gallery, Enter and Escape).
- Consequence:
  - Shadow offsets are rounded to whole device pixels (up to half a pixel off at the page's resolution), and the blur is a box approximation of a Gaussian.
  - Shadows are bitmaps in PDF at 150 dpi: a very large blur is soft anyway, but the edge of a hard shadow (blur 0) is 150 dpi.
  - Pages with a shadow render untiled in the GUI's viewport, so a very large page with many shadows costs more than one without. The tiled path is the default for everything else.
  - The GPU backend has no blur; `Rasterizer` draws pages with a shadow with tiny-skia (the GUI never uses the GPU for page rendering since ADR 0013).
  - WordArt cannot be spell checked, and its text is not edited in place on the canvas (the panel edits it).
  - The BorderArt colours cannot be changed; a user-supplied pattern would need a new asset type.
