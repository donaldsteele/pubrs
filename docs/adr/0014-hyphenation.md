# 0014 Hyphenation and bounded justification: a shadow text with soft hyphens

- Context: parley 0.12 has no hyphenation and no soft-hyphen handling. U+00AD is a line-break opportunity (UAX 14) and is shaped as an invisible zero-width cluster, so a break there ends the line with nothing drawn and no width reserved. parley also does not report where a line ended while breaking (only its advance and break reason), and justification is all or nothing: `Alignment::Justify` spreads the free space over word spaces with no upper bound. Story offsets are in characters and must never include characters the user did not type.
- Decision:
  - **Shadow text.** For a paragraph with `hyphenate: true` and a language with bundled patterns (`hypher`, see `ASSETS.md`), `flow.rs` shapes a *shadow* text: the paragraph text with a U+00AD inserted at every pattern point (words of at least left+right minimum letters, per `Lang::bounds`; pattern lookups are memoised per thread). Typed soft hyphens are kept as they are, whether or not `hyphenate` is on, and a word next to one is not hyphenated again. Inserted markers are kept in a sorted list; `Shadow::to_orig`/`from_orig` map bytes between the two texts. Everything that leaves the flow (line `chars`, caret offsets, glyph text ranges, overflow offsets) is counted on the original text, so the story never holds an inserted character.
  - **Line decisions (`hyphen::LineCx`).** Before breaking, an unconstrained layout of the same shaped text gives the x of every cluster. After each `break_next`, the line's end is found by matching its advance against those positions. If the line ends at a soft hyphen, the hyphen's width is read from the font (U+002D in the run's font at its size, via skrifa) and the break is taken only if content plus hyphen fits. A *typed* soft hyphen is then taken. An *inserted* one is taken only if the line without that word would be loose: justified lines when the gap exceeds what word spaces may absorb, ragged lines when the gap exceeds 12% of the width (`RAGGED_ZONE`). Otherwise the line is reverted and re-broken with a max advance just below the candidate, which finds an earlier point in the same word or the space before it. A soft hyphen in the first word of a line is always taken when it fits (there is no earlier break).
  - **Hyphen glyph.** The width is reserved by recording the line's width as `max - hyphen` with `BreakLines::set_prior_line_width`, so right, centre and justified alignment all treat the hyphen as part of the line. The line box then gets one extra glyph (the font's hyphen, empty text range at the line end) appended to its last run; soft hyphens inside a line are dropped. The caret at the line end is before the hyphen.
  - **Justify limits.** `justify_limits { max_word_space, letter_spacing }` (defaults 1.33 and 0.05 once set; `{}` means both defaults). For each justified line that is not the last of its paragraph the free space is compared with the word-space cap (`(max_word_space - 1)` times the line's word-space advance) and the letter-spacing cap (`letter_spacing` times the font size per character gap). Within the first cap parley justifies as is. Between the two, parley is told to stretch word spaces by exactly the cap (via `set_prior_line_width`) and the rest is added to the glyph, caret and underline positions as letter spacing; the line box keeps its full width. Beyond both, the line is left short (start aligned). The last line is never stretched; parley already skips it.
  - **LD2: unset = v0.1 behaviour.** `justify_limits` is an `Option`; every v0.1 document, every existing golden and the bakery sample leave it unset and take the old code path unchanged (no extra pass, no width adjustment): justification is unbounded as before. Likewise `hyphenate` defaults to off. The built-in styles do not enable limits; the M30 templates should. The Paragraph dialog's "Limit word and letter spacing" checkbox sets the field. `{"unbounded": true}` is the explicit "no limits" value: it overrides limits a paragraph style sets, resolves to the unset state, and takes the old code path exactly. The dialog writes it when the box is unticked.
  - **Languages.** Only languages whose pattern licence is recorded in `ASSETS.md` are enabled: en, de, es, fr, pl, pt. A paragraph asking for another language gets no hyphens and a `hyphenation_unavailable` validate note. English US's terms are a notice-preserving permissive grant outside the Locked Decision 5 list; the owner confirms.
- Consequence:
  - Paragraphs that are justified with limits, or contain a soft hyphen, cost one extra unconstrained break pass and a per-line scan (linear in the line); all other paragraphs are untouched. Pattern lookup for a hyphenating paragraph is eager over its words (memoised), while the *decisions* are lazy, made only at line ends.
  - Shaping across an inserted marker can differ slightly from the unmarked text (kerning and ligatures at the point), and only when hyphenation is on.
  - Right-to-left text (cluster order is not logical order), or a line end the analysis cannot place, makes `LineCx` unsound. The paragraph is then laid out again once with no inserted soft hyphens (typed ones keep plain parley behaviour: invisible, no hyphen drawn), so no unreserved hyphen can overhang the column. Justify limits are skipped for such a paragraph.
  - parley's hidden `set_prior_line_width` is relied on; the layout goldens would catch a change in its meaning.
