# 0018 Commercial print output: CMYK and spot colour, PDF/X-4 as an incremental update, PDF/A-2b

- Context: T14 (M22). krilla 0.8.2 has PDF/A and PDF/UA validators but no PDF/X, and its own output intent is always sRGB. Print shops want exact CMYK and spot values, a CMYK output intent, trim and bleed boxes, and a file they can trust. Owner decision 7: no colour management and no soft proof in pubrs; PDF carries the values as entered.
- Decision:
  - **Colour mapping (`pdf.rs`, from `ResolvedInk::spec`).** RGB stays RGB. A CMYK swatch is `DeviceCMYK`, each component scaled by the tint (`c * tint / 100`). A spot colour is a `/Separation` whose colorant is a custom name equal to the spot's name, with the swatch's CMYK as the alternate and the tint percent as the tint. This applies to fills, strokes, text (including the synthetic-bold outline), underline rectangles and gradient stops.
  - **Quantisation.** krilla stores every component as a `u8`, so a value `p` percent is written as `round(p / 100 * 255) / 255` (C 33.3 gives 85/255 = 0.33333). A tint of 40% on a spot is exactly 102/255 = 0.4. This is the finest resolution krilla offers; it is below what any press resolves, but it is why a value read back from the PDF can differ from the swatch by up to 0.2 percent. Tests assert the quantised values.
  - **Gradients.** krilla writes one colour space per shading (that of the first stop). Stops are therefore brought to a common space: all stops of one spot stay Separation; CMYK and spot stops (or different spots) become DeviceCMYK, using each spot's alternative at its tint; anything mixed with RGB falls back to RGB screen colours. A gradient from a spot colour to white thus becomes RGB; use a CMYK or spot white if the gradient must stay in the print colour space.
  - **PDF/X-4 is an incremental update (`pdfx.rs`).** krilla writes PDF 1.6 with `cmyk_profile` set to the output profile and `no_device_cs` on, with a classic cross-reference table. `make_pdfx4` appends: the ICC stream (`/N 4`); an OutputIntent (`/S /GTS_PDFX`, OutputConditionIdentifier `(Custom)`, OutputCondition `(Generic CMYK (SWOP-like))`, RegistryName `(http://www.color.org)`, DestOutputProfile); the re-stated catalog with `/OutputIntents`; the Info dictionary with `/GTS_PDFXVersion (PDF/X-4)` and `/Trapped /False`; the XMP stream with `pdfxid:GTS_PDFXVersion` and `pdf:Trapped`; a new cross-reference subsection per object and a trailer with `/Prev`. The original bytes are never moved, so offsets stay valid and krilla's work (fonts, images, boxes) is untouched. krilla's XMP stream is not compressed, so it is edited in place and written again with a new `/Length`; had it been compressed the update would have returned `None` and the export would fail rather than produce a file without the marker. TrimBox and BleedBox come from krilla's `PageSettings` on every page.
  - **RGB under a CMYK intent.** PDF/X-4 allows RGB only if it is colour-managed. With `no_device_cs`, krilla writes RGB colours, RGB images, soft-mask groups and transparency groups as ICCBased sRGB, never DeviceRGB. CMYK is then also ICCBased (`N 4`, the output profile itself), carrying the same numbers DeviceCMYK would. The staged checker's `DeviceRGB` walk is kept as the safety net. DesignCraft instead rewrote transparency groups to DeviceCMYK in place (`cmyk_group_spaces`); that is not needed here and is dropped.
  - **Images.** krilla's `/Interpolate true` (which pubrs set on passed-through PNG and JPEG for smooth screen scaling) is forbidden by PDF/X-4 and PDF/A-2b, so it is off whenever a standard is selected. Plain exports are unchanged.
  - **The checker (`pdfx::check`).** Ported from DesignCraft `check_pdfx4`: version at most 1.6; output intent, destination profile, Info and XMP version keys; no `/Interpolate true`, no `/Encrypt`; a TrimBox on every page; no Type 3 fonts; and a walk with `hayro-syntax` over page content, images, forms, patterns, shadings, soft masks and groups for DeviceRGB under a CMYK intent. Every PDF/X-4 export runs it; any issue makes the export fail with an error naming the issues. veraPDF has no PDF/X profile, so this checker is the PDF/X gate.
  - **PDF/A-2b.** krilla's `A2_B` validator, unchanged. It forces device-independent colours, so CMYK and spot alternatives are ICCBased against the bundled profile (`cmyk_profile`). The file needs a creation date; the current time is used. veraPDF 1.30.2 (pinned by digest) validates the fixtures in CI.
  - **Profile.** `assets/icc/generic-cmyk-swop-like.icc` (ASSETS.md), embedded with `include_bytes!`. `output_intent_icc` replaces it for PDF/X-4; the header must be class `prtr`, colour space `CMYK`, signature `acsp`, or the call is refused with a hint. The OutputCondition is then "Custom CMYK output profile".
  - **Tagged PDF.** `tagged: true` sets krilla's tag tree: text runs are `Span`s inside a `P` per frame, pictures are `Figure`s whose `/Alt` is `ImageFrame.alt_text`, and rules, shapes, fills and crop marks are artifacts. Alt text lives in the document (`ImageFrame.alt_text`, schema 5, omitted when empty) and reaches the writer as `PdfOptions.alt_text` keyed by frame.
  - **Print package.** A zip with `<name>-pdfx4.pdf`, `<name>.pubrs` and `README.txt` (fonts used, swatches with CMYK and spot values). The PDF and the `.pubrs` are stored, not deflated, so the package size does not vary run to run.
- Consequence:
  - PDF/X-4 output is only as strong as the checker; trapping, overprint and ink-coverage limits are not checked.
  - Colour is quantised to 8 bits per component.
  - A gradient that mixes RGB with CMYK or spot stops is written in RGB.
  - CMYK in PDF/X-4 and PDF/A-2b is ICCBased, not DeviceCMYK. The numbers are identical; a printer's preflight that insists on DeviceCMYK should use the plain export or a profile-less workflow.
  - `hayro-syntax` becomes a normal dependency of `pubrs-render` (default features off).
