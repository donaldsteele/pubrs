# 0011 GUI adapter: hardware on any API first, then bundled Mesa llvmpipe

- Context: on Windows without a usable DX12/Vulkan GPU driver (virtual machines, remote sessions, older Intel GPUs that wgpu's DX12 backend rejects), egui drew the window with WARP ("Microsoft Basic Render Driver"). Measured on the windows-latest runner (4 cores, no GPU), with the sample open and the cursor moving over a 1000×700 window: 76% of the machine, 5 fps, about 0.5 CPU-seconds per frame. Our UI code took 0.3 to 2 ms of that; idle stayed at 0%. The cost scales with window area and does not change with present mode, dithering, FXC or DXC, or the DXGI swapchain kind. Until now pubrs limited wgpu to Vulkan/Metal/DX12 (ADR 0004), so a GPU reachable only through OpenGL was never tried. On the same runner, Mesa's llvmpipe (mesa-dist-win `opengl32.dll` with `GALLIUM_DRIVER=llvmpipe`) drew the same window at 64 fps (vsync) for 28 to 36 ms of CPU per frame, 16× cheaper than WARP.
- Decision:
  - wgpu enumerates Vulkan, Metal, DX12 and OpenGL, and `crates/pubrs-app/src/adapter.rs` picks the adapter. Order: hardware first, then llvmpipe/lavapipe, then other software (WARP). Within each group, Vulkan/Metal/DX12 before OpenGL, then discrete, integrated, virtual, unknown. OpenGL renderers count as software by name as well as by wgpu's device type, because wgpu reports OpenGL-on-D3D12 over WARP as an unknown device.
  - The x64 MSI bundles mesa-dist-win 26.2.4 (`opengl32.dll`, `libgallium_wgl.dll`, about 62 MB uncompressed; pinned and SHA-256-checked by `packaging/windows/fetch-mesa.ps1`) in `bin\mesa`, with a copy of `pubrs-app.exe` that WiX `CopyFile` makes at install time.
  - pubrs-app imports `opengl32.dll` at load time and Windows looks in the exe's folder first, so Mesa cannot be switched on inside a running process. Putting Mesa next to the main exe would also hide a VM's own OpenGL driver. Instead, when the selector finds no hardware adapter and `bin\mesa\pubrs-app.exe` exists, the selector fails on purpose. pubrs then runs that copy with the same arguments, `GALLIUM_DRIVER=llvmpipe` and `PUBRS_MESA=1`, and exits with its exit code (`crates/pubrs-app/src/mesa.rs`). Machines with any GPU never load Mesa. `PUBRS_NO_MESA=1` turns the restart off. If the copy cannot be started, pubrs stays on the system's software adapter.
  - The window renderer is logged at start-up and shown in Help → About. When it is software, the status bar shows "Drawing without a GPU". `PUBRS_PERF=1` logs frames per second, UI and paint time, page rasters and repaint causes once a second.
- Consequence: machines whose GPU wgpu reaches only through OpenGL draw on it, and machines with no GPU draw with llvmpipe instead of WARP. Start-up on GPU-less machines takes one extra process launch. The MSI carries third-party binaries; their licences (Mesa MIT, mesa-dist-win MIT, LLVM Apache-2.0 with LLVM exceptions) are installed as `bin\mesa\THIRD-PARTY-NOTICES.txt`. mesa-dist-win has no ARM64 build, so the ARM64 MSI has no Mesa and still uses WARP on GPU-less ARM64 Windows. CI runs the full GUI self-test through the Mesa restart on the GPU-less Windows runner, and the release workflow checks that the installed MSI draws with llvmpipe there. Linux is unchanged: llvmpipe Vulkan still wins over llvmpipe OpenGL.
