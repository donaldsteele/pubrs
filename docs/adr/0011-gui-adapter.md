# 0011 GUI adapter: hardware on any API first, software last

- Context: on Windows without a usable DX12/Vulkan GPU driver (virtual machines, remote sessions, older Intel GPUs that wgpu's DX12 backend rejects), egui drew the window with WARP ("Microsoft Basic Render Driver"). Measured on the windows-latest runner (4 cores, no GPU), with the sample open and the cursor moving over a 1000×700 window: 76% of the machine, 5 fps, about 0.5 CPU-seconds per frame. Our UI code took 0.3 to 2 ms of that; idle stayed at 0%. The cost scales with window area and does not change with present mode, dithering, FXC or DXC, or the DXGI swapchain kind. Until now pubrs limited wgpu to Vulkan/Metal/DX12 (ADR 0004), so a GPU reachable only through OpenGL was never tried.
- Decision: wgpu enumerates Vulkan, Metal, DX12 and OpenGL. `crates/pubrs-app/src/adapter.rs` picks the adapter: hardware before software, then Vulkan/Metal/DX12 before OpenGL, then discrete, integrated, virtual, unknown. OpenGL renderers are counted as software by name as well as by wgpu's device type, because wgpu reports OpenGL-on-D3D12 over WARP as an unknown device. The window renderer is logged at start-up and shown in Help → About. When it is software, the status bar shows "Drawing without a GPU", with a hover text on installing the driver or turning on 3D acceleration. `PUBRS_PERF=1` logs frames per second, UI and paint time, page rasters and repaint causes once a second.
- Consequence: machines whose GPU wgpu reaches only through OpenGL now draw on it. Machines with no GPU at all still use WARP. On the same runner, Mesa's llvmpipe (`opengl32.dll` from mesa-dist-win with `GALLIUM_DRIVER=llvmpipe`, through glow) drew the same window at 64 fps and 28 ms CPU per frame, 16× cheaper than WARP. Bundling it (about 60 MB uncompressed) is listed in TODO.md as an option, not done. Linux CI is unchanged: llvmpipe Vulkan still wins over llvmpipe OpenGL.
