# 0015 Break characters, keeps and drop caps

- Context: Publisher has column, text-box and page breaks, keep-with-next, keep-together, widow/orphan control and drop caps. Story offsets are in characters and paragraphs are split on `\n`, so a break must be one character inside a paragraph. pubrs has no autoflow: nothing adds pages or frames for overflowing text. parley 0.12 shapes one paragraph per layout, ends a line at a newline-class character (`\n`, CR, U+2028, U+2029) with `BreakReason::Explicit` and draws no glyph for it.
- Decision:
  - **Code points.** Column break U+000E (the code Word's binary format uses for one), frame break U+001D (GROUP SEPARATOR; no typed text contains it), page break U+000C (form feed). All are ASCII controls, one byte in UTF-8, written by JSON as `"\u000e"`, `"\u001d"` and `"\f"`, and round-trip through `document.json`. `pubrs_core::text::BreakKind` maps them. `normalize_newlines`, insert and delete treat them as ordinary characters; find never matches across one unless the query holds it, and a break is never part of a word.
  - **Layout.** `flow.rs` shapes each break as `\n` (same byte length, so every offset map holds). parley ends the line there; the flow pairs the k-th explicit line end with the k-th newline-class character of the shaped text and, for a break, moves the cursor before the next line: a column break to the next region (column, or the next frame after the last column), a frame break to the next region in another frame, a page break to the next region whose frame is on a later page. Regions carry the rank of their frame's page among the chain's pages (`None` on masters), which is in the cache key and does not change when other pages are added. The break character belongs to no line (like the `\n` between paragraphs): the line before ends before it and the next line starts after it, so the caret can sit on both sides; it draws nothing. A justified line ending at a break is not stretched.
  - **Autoflow does not exist.** A page break continues in the next frame of the chain on a later page. If there is none, the rest of the story overflows from the character after the break and `text_overflow_status` reports it; no page is added. (The plan's "autoflow when the chain ends" waits for an autoflow feature, TODO.md.)
  - **Keeps.** Before each paragraph the flow notes its cursor and `placed.len()`; frames are filled only at the end, so a rewind is a truncate and a cursor restore. A paragraph's own rules (`keep_together`, `widow_orphan` n >= 2) are checked after it is flowed: if it is split and does not start at the top of its region, it is flowed again from the top of the next region (keep together, only when the paragraph fits in that region; or fewer than n lines at the bottom); if fewer than n lines end up at the top of the last region, the region break is moved up so that region gets n lines, or the paragraph moves whole when the region before would keep fewer than n. At most two extra passes per paragraph. A pass that overflows (the first did not), or a keep-together move that still splits the paragraph, is undone and the last good pass stands. Keep with next is checked after the next paragraph: if it starts in a later region than the kept paragraph ends, the flow rewinds to the first of the run of keep-with-next paragraphs that start in that region and flows them again from the top of the next region. A rewind never reaches more than one region back, never moves a paragraph that starts at the top of its region, moves each paragraph for keep-with-next at most once, and never moves into a region that does not exist. When a rule cannot be met the paragraph is laid out as usual. **Keeps never cost visible text:** a keep-with-next move whose re-flowed paragraphs overflow is undone, and when the story overflows after any keep moved a paragraph, it is flowed again without keeps and that layout is used if it shows more of the story. Paragraphs that contain a break character skip their own keeps.
  - **Drop caps.** `drop_cap {lines, chars}`: the first `chars` characters (stopping at a break or a line or paragraph separator) are left out of the paragraph's parley layout and shaped on their own in the first run's style at a size S with `S * cap_height = body_size * cap_height + (lines - 1) * line_height` (cap height from the font's OS/2 table, 0.7 if absent), so the cap reaches from the first line's cap height to the baseline of line `lines`. The first `lines` lines in the cap's region are indented by its advance plus a quarter em (first-line indent is ignored), and the paragraph starts in the next region when the cap's lines do not fit below it. The cap's glyph runs are put first in the first line's runs, on the actual baseline of line `lines` (or where it would be, for a shorter paragraph, which then keeps the cap's lines). Middle and bottom vertical alignment count the cap's baseline as well as the lines. The first line's `chars` start at the paragraph start and its carets run across the cap, so the cap characters stay in the story and can be hit.
  - **Carets are frame-local.** parley measures caret positions from the line's start; until M15 the flow passed them on as they were, so the editing caret sat left of indented or inset text by that amount. Carets now add the line's x and match glyph x, which the drop cap's carets (left of the line's text) need. No golden holds carets.
  - **LD2.** All four fields are `Option` and unset means the earlier layout bit for bit: no rewind, no cap, no extra pass. The built-in styles set none of them; the M30 templates should set `widow_orphan = 2` in body styles (TODO.md).
- Consequence:
  - Keeps cost at most four flows of a paragraph (three passes and an undo) and one re-flow of a run of keep-with-next paragraphs in one region, and only for paragraphs that set them; a story that overflows after a keep moved something is laid out twice; the per-story cache still recomposes only changed stories.
  - A keep-with-next paragraph that itself spans two regions is not moved (that would reach two regions back); its last lines are not split off to join the next paragraph.
  - The cap is drawn in one style even when its characters have several; right-to-left paragraphs get the cap on the left.
